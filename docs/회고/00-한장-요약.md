# 한 장 요약

이력서·포트폴리오에 그대로 붙이는 용도. 길이별로 세 버전.

---

## 3줄 버전 (이력서 프로젝트 항목)

> **BodyBuilder** — 웹캠 모션 인식 협동 웹게임 (2026.07 ~ 08, 6인 / Frontend)
> 웹캠으로 인식한 플레이어의 팔이 그대로 지형이 되어, 캐릭터가 굴러갈 다리를 함께 놓는 실시간 협동 게임.
> React 19 + MediaPipe 온디바이스 포즈 추론, WebRTC Mesh 화상통화, 서버 권위(dyn4j) 물리 시뮬레이션.
> **담당**: 포즈 인식 안정화(속도 적응형 스무딩), WebRTC 화상통화 초기 설계·구축, 미디어 장치 설정 시스템, 사운드/BGM 시스템, Google 소셜 로그인, 주요 페이지 UI.

## 10줄 버전 (포트폴리오 상단)

> 별도 장비 없이 **웹캠 하나로** 몸을 게임 컨트롤러로 바꾸는 4인 협동 웹게임입니다.
>
> 브라우저에서 MediaPipe Pose Landmarker를 GPU delegate로 직접 구동해 어깨·팔꿈치·손목 6개 관절을 추적하고,
> 그 좌표를 서버로 보내면 서버의 dyn4j 물리 엔진이 이를 지형(캡슐 선분)으로 변환해 시뮬레이션합니다.
> 계산 결과 프레임만 방 전체에 브로드캐스트하기 때문에 **모든 플레이어가 항상 동일한 결과**를 봅니다.
> 동시에 WebRTC Mesh로 서로의 얼굴과 목소리를 공유해, 자세를 맞추는 과정 자체가 협업이 되도록 만들었습니다.
>
> 저는 프론트엔드로 참여해 **WebRTC 화상통화 기능을 처음부터 설계·구축**했고,
> **포즈 인식 좌표의 안정화**를 단독으로 담당했습니다. 플레이어의 관절이 그대로 게임 지형이 되는 구조라
> 관절의 미세한 떨림이 곧 물리 오류로 이어졌는데, 움직임 속도에 따라 스무딩 강도를 바꾸는 방식으로
> 정지 시의 떨림과 빠른 동작에서의 지연을 함께 해결했습니다.
>
> 그 외 마이크/카메라 장치 선택과 음량을 관리하는 설정 시스템, 페이지 전환에 걸쳐 끊기지 않는 BGM 시스템,
> Google 소셜 로그인, 메인·로비·마이페이지 등 주요 화면의 UI를 담당했습니다.
>
> 실시간 P2P 연결의 경쟁 조건(race condition), 센서 입력의 노이즈와 결측치 처리, 브라우저 미디어 장치 권한 등
> "값이 항상 정확하게 오지는 않는 시스템"에서만 나오는 문제들을 다뤘습니다.

## 팩트시트

정량 지표. 면접에서 규모를 물을 때 쓴다. **모두 레포에서 직접 센 값이다.**

| 항목 | 값 |
| --- | --- |
| 기간 | 2026.07.18 ~ 2026.08.07 (3주) |
| 팀 구성 | 6명 (Frontend 3, Backend 3) |
| 내 역할 | Frontend |
| 전체 커밋 | 457 (머지 포함) |
| 내 커밋 | 31 (`최준혁` 21 + `choi` 10) |
| Frontend 코드 | 149개 파일 / 약 34,000 LOC (ts·tsx·css) |
| Backend 코드 | 252개 파일 / 약 23,100 LOC (java) |
| 테스트 파일 | Frontend 31개 (Vitest), Backend 51개 (JUnit 5) |
| 배포 | GitLab CI (validate → test → deploy) → AWS EC2, Docker Compose, Nginx + Let's Encrypt |

### 기술 스택 (내가 실제로 만진 것 **굵게**)

**Frontend** — **React 19**, **TypeScript 6**, React Router 7, **Vite 8**, **@mediapipe/tasks-vision**, **WebRTC**, **@stomp/stompjs + SockJS**, Vitest, MSW, oxlint, **CSS(Container Query)**

**Backend** — Java 21, Spring Boot 3.5.14, Spring WebSocket(STOMP), dyn4j 6.0.0, Spring Data JPA, MySQL 8.4, Flyway, Redis/Valkey, Spring Security, springdoc-openapi

**Infra** — Docker Compose, Nginx, GitLab CI, AWS EC2, Let's Encrypt

> ⚠️ 면접에서 스택을 나열할 때 **내가 안 만진 걸 만진 것처럼 말하지 말 것.**
> dyn4j 물리 엔진과 Spring 백엔드는 팀원 작업이다. "팀이 이렇게 했고, 나는 이 부분을 했다"로 분리해서 말한다.
> 구조를 이해하고 있다는 것과 내가 만들었다는 것은 다르고, 면접관은 그 차이를 반드시 판별한다.
